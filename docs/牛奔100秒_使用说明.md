# 牛奔100秒 · XBuilder 项目使用说明

## 一、这是什么

《坚持100秒》的 **XBuilder / spx 改编版**。用七牛云 XBuilder（goplus/builder）打开即可运行，产物是标准 `.xbp` 项目包。

- 平台：XBuilder（x.qiniu.com / xbuilder.com），底层 spx 引擎 + XGo
- 舞台：480 × 360（spx 默认）
- 体积：28 KB（xbp）/ SVG 资源 38.5 KB

## 二、怎么打开

**方式 A（推荐）**：XBuilder 在线版 → 导入项目 → 选择 `牛奔100秒.xbp`

**方式 B**：本地开发
```bash
# 需要 Go 1.21.3+ / Python 3.8+ / XGo
cd 牛奔100秒
xgo run .          # 或 spx run -path .
```

**方式 C**：在 XBuilder 编辑器里手动新建项目，再把本目录内容拷进去（见下方文件结构）

## 三、操作方式

| 按键 | 动作 | 对应障碍 |
|---|---|---|
| `↑` / `W` / `空格` | 跳跃 | 橙黄色**低矮牛**（卧倒牛、犊牛、滚草球牛） |
| `↓` / `S` | 滑铲 | 紫蓝色**高架牛**（倒挂牛、吊绳牛、举铃牛） |
| `←` / `A` | 换到上一层 | 深红色**阻挡牛**（正面立牛、独角冲牛、红斗篷牛） |
| `→` / `D` | 换到下一层 | 同上 |

三种牛对应三种躲法，**颜色即语义**：

- 🟠 橙黄 = 低矮，跳过去
- 🟣 紫蓝 = 高架，钻过去
- 🟥 深红 = 满层，换道躲
- 🟡 金色 = 奖励牛，主动撞它 +100 分
- 👑 王冠 = 牛王，超大体型，占满中间层

## 四、三条赛道

| 赛道 | 加速度 | 末速 | 任务箱 | 通关要求 |
|---|---|---|---|---|
| **晨曦** | 0.12 | 20 m/s | 无 | 活过 100 秒 |
| **霓虹** | 0.06（减半） | 14 m/s | 20/38/55/72/88s | 活过 100 秒 **且完成 2 个任务** |
| **熔岩** | 0.12 + 任务期 ×1.08 | 21.6 m/s | 18/34/50/64/78/90s | 活过 100 秒 **且完成 3 个任务** |

速度只增不减，最后 10 秒最快。障碍间距随时间微增，抵消部分加速带来的反应窗口坍缩。

任务箱落在**你当前所在跑道**上 —— 顺路就接到（默认接），主动变道避开 = 放弃本次。接与不接都是有意识的取舍。

## 七、实现要点（改代码前必读）

### 1. spx 是纯 2D，没有伪 3D
原型的 3 车道俯视改为**三个 Y 高度层**（上 100 / 中 0 / 下 −100），障碍从右向左推进。

### 2. 克隆体自己决定种类和层
`broadcast` 是广播给**所有**精灵的，无法定向投递给单个新克隆体。所以：
- `Stage.spawnObstacles()` 只判断"何时生成"，然后调 `Cow.spawnCow()`
- 具体牛种、所在层、造型变体，全在 `Cow.onCloned` 里用 `rand()` 自己抽

### 3. 自定义函数用标准 Go 语法
```go
func setupTrack(id int) { ... }          // 在 Stage.spx 内
Stage.setupTrack 1                        // 跨精灵直接调用（Stage 是全局变量）
```

### 4. 数字转字符串必须用 strconv
```go
import "strconv"
Stage.say "得分 " + strconv.Itoa(score), 1.5
```

### 5. 舞台坐标
原点居中，480×360 → x ∈ [−240, 240]，y ∈ [−180, 180]。生成点 x=280（右侧屏外），销毁线 x=−280。

### 6. 碰撞用 `touching`
`touching(Player)` 是矩形 + 像素级检测。**pivot 决定判定框**，所以每头牛的 pivot 都按身体实际位置设置（见各 `index.json`）。

### 7. 官方代码组织规范（重要，已按此重构）
依据 `spx-gui/src/utils/spx/skills/spx-project/SKILL.md`：

| 规范 | 本项目做法 |
|---|---|
| 代码顺序：var → func → 事件处理器 | 六个 .spx 全部符合 |
| `var` 块按类型拆分 | `main.spx` 分 5 块（整数/浮点/字符串/布尔/列表） |
| **精灵实例无需声明** | 引擎按精灵名自动生成全局变量，`main.spx` 不再声明 |
| 函数定义须在所有 `onXxx` 之前 | `Stage.spx` 10 个函数全部前置 |
| 顶层语句放末尾 | `run "res", {...}` 置于文件末尾 |

### 8. `onMsg` 带数据的正确语法
官方定义是 `onMsg (msg, data) => {}`（监听**任意**消息）。若要监听指定消息并取数据，用**全局变量**更直观：

```spx
// Stage.spx 主循环里写入
stepLen = baseStep + accel * elapsed * 0.42

// Cow.spx 克隆体直接读
changeXpos -stepLen
```

本项目已改用全局变量传递移动步长，避免了 `onMsg` 的两种写法混用。

### 9. List 方法全小写
官方 `references/apis.md` 明确为 `List.init` / `List.len` / `List.at`（**全小写**）：

```spx
slotTimes.init(20, 38, 55, 72, 88)   // 初始化
if taskSlotIdx >= slotTimes.len { }    // 长度
slotTimes.at(taskSlotIdx).Float()      // 取值 → Value，再 .Float()
```


## 八、本地 AI 协作（官方推荐路径）

XBuilder 内置 Copilot **只能答疑、不会直接改项目代码**。要让它真正改代码，官方给的路径是：导出项目 → 本地编辑 → 打包导入。

官方为此提供了两份 **skills 规范**，正好补上通用 AI 工具的知识盲区：

| 仓库 | 内容 |
|---|---|
| `github.com/goplus/builder/tree/dev/spx-gui/src/utils/xgo/skills/xgo-language` | XGo 语言规范（classfile 语法、lambda 风格事件、函数重载、List/Map 字面量） |
| `github.com/goplus/builder/tree/dev/spx-gui/src/utils/spx/skills/spx-project` | spx 项目规范（文件组织、var/func/evt 顺序、API 全表 `references/apis.md`、AI Interaction） |

把这两份 skill 喂给本地 AI（CodeBuddy / Claude Code / Cursor 等），它就能按官方规范写 `.spx` 代码，而不用猜。

**本项目用的完整 API 表**（`references/apis.md`）可以核对：
```
https://github.com/goplus/builder/blob/dev/spx-gui/src/utils/spx/skills/spx-project/references/apis.md
```

### 本仓库已配好的三套校验器

改完代码先跑一遍，避免把不合规的代码打回 XBuilder：

